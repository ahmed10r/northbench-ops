Where to keep the AI prompts that work, so you stop rewriting them

A prompt you cannot find again is a prompt you never wrote. The value is not in the words you typed once, it is in the file that kept them.

The short answer

  • Keep prompts where you keep your other work notes, not inside one chat window.
  • One prompt per entry, with a plain name describing the job it does.
  • List the variables separately: the details you swap each time it is used.
  • Note when not to use it. That note is what stops a bad result six months from now.
  • Test a prompt a second time, on a different day, before you trust it.

Four lines beside every prompt

  1. Name: the job in five words, so you can find it by searching your own file.
  2. The prompt itself, complete, with the parts you change left in brackets.
  3. What you swap: the list of details that differ each time you use it.
  4. When it fails: the case where this prompt gives you something you have to rewrite anyway.

Why the chat window is the wrong home

Chat windows are convenient and forgetful. They sit behind a login, they change shape without asking you, they give you almost no way to organise anything, and searching them means scrolling past conversations you had at midnight about something else entirely.

Any file beats any chat history, as long as you can search it. A folder of plain text, a note in the app you already use for work, a single sheet with one prompt per row - all of them are better than a prompt that exists only in a thread you cannot find.

  • If a colleague needs a prompt, send the entry, not ten screenshots.
  • Version the prompt: when you improve it, keep the old line until the new one has worked twice.
  • Write the reason a prompt is worded as it is. Without it, you will edit away the part that was doing the work.

Ten minutes to start

  • Take the last three prompts you actually reused and write them down today, while you still remember why they worked.
  • Add the fourth line each time one fails, and the file improves without any extra effort.
  • Once a month, delete the entries you have not opened. A short file is a file you use.
  • Keep the few prompts you know inside out close to hand, and let the rest be reference.

Questions people actually ask

How many prompts do I need?

Fewer than you think. Ten prompts you have adjusted to your own work will do more than a hundred you browse and never adapt.

Should I share them with my team?

Only after they have survived a second test, and always with the when-not-to-use note attached. A shared prompt without its caveats is how a team learns to distrust prompts.
